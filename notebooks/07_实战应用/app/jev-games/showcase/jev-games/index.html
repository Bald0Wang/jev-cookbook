一个简单的问题

同一个模型，
为什么表现不同？

模型并不是拿到任何信息都能做好决定。
它需要知道当前发生了什么、可以做什么，以及上一轮动作带来了什么结果。下面用贪吃蛇和扫雷把这件事讲清楚。

先看结论

不是多写一句提示词，
而是把问题交代完整。

左边和右边用的是同一个 Jev。区别在于，软件给它的状态和可选动作不同。

01 / 告诉它眼前发生了什么

当前棋盘不够

蛇走过哪里、哪些格子安全、哪些动作已经试过，这些都可能决定下一步。

02 / 只让它选择能执行的动作

先整理选择范围

程序负责过滤撞墙、走回身体和明显危险的方向，Jev 在剩下的选项里做判断。

03 / 把结果带回下一轮

让每一步有记忆

吃到食物、进入循环、信心变低，这些结果会变成下一次请求的一部分。

为什么会这样
差别不在“聪不聪明”，
在问题有没有说清楚。
下面把两边的差异拆成普通人也能复述的几句话。
左边为什么更差？
它不是每一步都错，而是在一个缺信息的问题上持续做局部正确判断。
  • 不知道自己刚才走过哪里
  • 只看到“离食物更近”这个线索
  • 没有收到“我正在重复”的提醒
  • 上一轮结果没有进入下一轮
右边为什么更好？
程序先把确定的信息整理好，再让 Jev 负责真正需要判断的部分。
  • 知道最近走过的轨迹
  • 知道哪些方向可以安全执行
  • 知道一条可行的脱困路线
  • 知道上一轮执行后的结果


把方法带走
以后接入别的模型，
也可以照这个思路。
模型只负责它擅长的判断，程序负责确定的规则和执行。
把状态写完整
不要只传一张截图。把历史、关系、限制和结果都变成字段。
state = {
  board,
  history,
  feedback
}
把选择写具体
不要让模型在整个世界里猜。先列出它现在真的可以执行的动作。
actions = [
  right,
  down,
  plannedPath
]
把结果传回来
一次决策不是结束。执行后发生了什么，要成为下一次判断的输入。
nextState = {
  ...state,
  result
}
