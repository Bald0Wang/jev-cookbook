# RLCD：公开证据、可推导机制与训练前验证设计

检索日期：2026-09-17。本文件只做文献检索、数学推导和实验设计，没有调用在线模型，也没有训练或微调模型。下面凡写“假说”“自拟目标”的地方都不是 TypeSafe 已披露算法。

## 1. 先明确已知与未知

TypeSafe 官方使用的全称是 **Reinforcement Learning for Calibrated Decisions（RLCD）**，并将新架构、新采样器和新训练算法并列描述。当前检索未找到可明确归属于 TypeSafe 的 RLCD 论文、奖励公式、梯度估计器、训练数据配方或可复现实现；这意味着我们有研究方向，暂时没有原算法规格。[TypeSafe 官方网站](https://typesafe.ai/)

官方 AI primer 进一步把 RLCD 画成**预训练语言模型之后的第三条后训练分支**，与 RLHF、RLVR 并列。这已经支持“从已有语言能力转向概率决策”的路线；但页面没有公布 JeV 使用哪个基座、修改了哪些网络层、参数量或完整训练过程。后训练来源与最终推理架构是两件事，不能据此宣称 JeV 就是某个公开 decoder 加分类头。[官方 AI primer](https://docs.typesafe.ai/introduction/machine-learning-primer)

**新增的一手边界：** 创始人明确表示不允许他所说的 latent reasoning，即 chain-of-thought，并将 System 2 放在代码组合层。本轮读取了项目内已由原页与官方 oEmbed 双重核验的[公开讨论记录](rlcd_public_discussion_zh.md)，据此将“模型先做隐藏的多步推理，再输出判断”从 JeV 主要机制假说中移除。[创始人原帖](https://x.com/CompleteSkeptic/status/2099981459541143995)

这句话不能解释成“网络没有 hidden states、不能有随机变量、没有多层计算、采样器绝不迭代”。普通表征向量与作者否定的 latent reasoning 不是同一概念；非自回归输出也不等于已证明单次前向。已披露的边界足以约束我们的功能设计，还不足以确定其具体网络。

同样需要区分 **RLCR**：Damani 等的 *Beyond Binary Rewards: Training LMs to Reason About Their Uncertainty*，其中全称为 Reinforcement Learning with Calibration Rewards。它给生成答案及数值信心的语言模型增加校准奖励。这是直接相关的一手研究，却不是 TypeSafe RLCD，也不是天然满足我们要求的非自回归概率输出架构。[RLCR 论文](https://arxiv.org/abs/2507.16806)

现阶段最有价值的问题不是“应该用 PPO 还是 GRPO”，而是：**模型输出的随机变量是什么、监督来自哪里、奖励作用于单个答案还是整个预测分布、采样器如何参与这个奖励。** 确定这几项后，优化器才有明确职责。

## 2. 校准的对象必须先定义

设 `x=(state, question, criteria)`，真实条件分布为 `q(y|x)`，模型报告的分布为 `pθ(y|x)`。

这里至少有三种不同量：

1. **事件概率**：例如在给定信息下“退款已完成”的概率。Boolean 的 `p_true` 属于这种语义。
2. **某个答案正确的概率**：模型先回答 `a`，再报告 `c=P(a正确|可用信息)`；RLCR 主要处理这种问题。
3. **执行某个动作的策略概率**：`π(a|x)` 是代理选择动作的频率。最优行动可以是确定的，即使事件本身很不确定。

例子：某事件实际发生率是 0.7。诚实预报是 `p=0.7`；如果只按猜中与否计分，最优动作始终猜“发生”。把这两个目标合在一个 softmax 里，很容易将“更会赢”误认为“概率更准”。

标准校准要求如 `P(Y=1 | p(X)=r)=r`。但恒定报告全体基准发生率也可能校准，所以还必须关注区分不同状态的能力。严格 proper scoring rule 同时评价概率质量，而不是只检查分箱后的误差。[Gneiting 与 Raftery，2007](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf)

二元 Brier 的总体分解把这点写得更明确。令 `F=p(X)`、`m(F)=E[Y|F]`：

```text
E[(F-Y)²] = E[(F-m(F))²] - Var(m(F)) + Var(Y)
             校准误差          分辨率          固有不确定性
```

校准误差越低越好，分辨率越高越好；只最小化前者会接受一个完全忽略输入的基率模型。例如两类等量状态的真实发生率分别为 0.1 与 0.9，恒报 0.5 完全校准，却没有分辨率，Brier 为 0.25；根据状态正确报告 0.1/0.9 同样校准，Brier 为 0.09。这里使用总体恒等式；有限数据的分箱估计另有抽样误差，不能把粗分箱上的 ECE 接近零当成证明。[Murphy 的 Brier 分解](https://journals.ametsoc.org/view/journals/apme/12/4/1520-0450_1973_012_0595_anvpot_2_0_co_2.xml)、[proper scores 的一般分解](https://arxiv.org/abs/0806.0813)

因此，复现的核心应当是**跨任务学习有语义的条件概率**：输入状态、问题与候选的意义改变时，概率也应随证据正确变化，并在未见领域保持可用。全局 temperature 只能调整已有分数的浓度，不能教会模型新的语义区分；从分布计算 confidence 更只是确定性统计，不是校准训练。后处理可以作为单独消融，但不能替代这项核心能力。评测至少同时报告 proper score、相对基率模型的 skill、分辨率、标签准确率及校准；每项都要在未见任务/文档上测，而不是只报告训练模板的平均值。

若题目是主观情绪/rubric，`q` 也可能定义为合格标注者的分布，而不是唯一客观真值。teacher 的分布只能定义一个模仿目标，不自动成为现实中的 `q`。

## 3. 为什么“采一个答案，答对就奖励”不够

限定如下：模型先从 `p` 采样一个类别 `A`，环境提供结果 `Y`，奖励 `r(A,Y)` 不直接依赖模型报告的 `p`。此时：

```text
J(p | x) = E[A~p, Y~q] r(A,Y)
         = sum_a p_a * E[Y~q] r(a,Y)
```

这是关于 `p` 的线性函数，最优解通常在概率单纯形的顶点，即把概率全部压到某个高收益动作。平局时也只是非唯一最优，不能识别完整真实分布。

对二元“答对得 1 分”：

```text
q = P(Y=1|x), p = P(A=1|x)
J_correct(p) = p*q + (1-p)*(1-q)
             = (1-q) + (2q-1)*p
```

只要 `q>0.5`，最优就是 `p=1`；`q<0.5` 时最优是 `p=0`。多采几个答案、把正确奖励取平均，仍然是同一个线性目标，无法自行修复校准。

**这不意味着一条训练样本只有一个真实结果，就不能学概率。** 如果奖励直接评分完整报告 `p`，即使每个 `x` 只有一个观测 `Y`，proper loss 仍在总体期望上识别条件概率；有限数据下要靠跨样本共享规律和适当正则化。真正有问题的是奖励函数对预测分布没有适当的约束，而不是“每题没有无限多次标签”。

给正确奖励加固定熵奖励也不普遍解决问题。二元情况下 `J_correct + τH(p)` 的最优为 `sigmoid((2q-1)/τ)`，一般不等于 `q`。因此“鼓励多样性”和“正确校准”不是同义词。

## 4. 直接分布头：CE/Brier 已经具备校准的目标

如果网络可以直接输出可微的概率向量，首要数学基线就是：

```text
L_log(p,Y) = -log p_Y
E[L_log | x] = H(q) + KL(q || p)

L_brier(p,Y) = sum_k (p_k - 1[Y=k])²
E[L_brier | x] = ||p-q||² + 1 - ||q||²
```

两者在可实现的总体最优下均以 `p=q` 为唯一最优。二元只报告 `p_true` 时，常用的 scalar Brier 是 `(p-Y)²`，相当于二类向量版的一半。

当 `pθ` 可微、`Y` 已知且候选数很小，反向传播这些 loss 即可，不需要将 `p` 先离散采样成某个概率字符串，再用 REINFORCE 估计梯度。把 `-L_brier` 改名为 reward 并不自动创造一个新的学习目标。

这也不表示“只用 CE 训练出来一定校准”：有限样本、模型失配、分布漂移、过拟合、标签偏差和不同正则化都会破坏理想条件。监督 CE/Brier 是必要对照，而不是未经测量就宣布它替代 RLCD。

如果要声明 RL 的贡献，至少应该展示：在相同数据、同一 backbone、相近计算量下，它在哪个指标上优于直接 proper-loss 训练；或者说明为何直接梯度根本不可用。

## 5. 与 parallel sampler 最紧密的一种可行机制

下面是**我们的候选机制**，基于已知 proper/kernel scoring 理论推导；不能称为“TypeSafe 就这样训练”。

这里采样的是同一问题的**候选决策结果**，不生成文字或隐藏推理链。因此它与“不允许 CoT”的披露不冲突；但“尚未被排除”不是官方确认，parallel sampler 一词本身也没有证明它采用下述奖励。

独立采样 `A,B ~ pθ(.|x)`，给一条真实结果 `Y` 定义：

```text
R_pair(A,B,Y) = 1[A=Y] + 1[B=Y] - 1[A=B]
```

其期望为：

```text
E[R_pair | x] = 2 sum_k p_k*q_k - sum_k p_k²
              = ||q||² - ||p-q||²
```

所以唯一最优为 `p=q`。前两项奖励与事实相符，第三项防止仅仅把所有样本压到同一答案。这是 Brier 目标的样本估计，与随意加熵奖励不同。

多样本版可使用 `M>=2` 个条件独立样本：

```text
R_M = (2/M) * sum_m 1[A_m=Y]
      - 1/(M*(M-1)) * sum_{m≠n} 1[A_m=A_n]
```

第二项必须排除自配对。它的期望仍是相同的 proper 目标；多个样本能在张量中并行获得，也可能降低估计噪声。这就提供了一条可以认真验证的技术联系：**新采样器不仅服务推理速度，也可能为训练提供分布级奖励所需的样本。**

对有序 Score，类似的样本目标是负 CRPS：

```text
L_CRPS = E|A-Y| - 0.5*E|A-B|
```

它利用等级距离，对分布而不是单个均值评分。Gneiting 与 Raftery 的论文第 4–5 节给出了 CRPS/energy/kernel scores 的独立样本表示；本文的有限类别指示函数形式是这一思路的具体推导。[proper/kernel scoring 理论](https://sites.stat.washington.edu/people/raftery/Research/PDF/Gneiting2007jasa.pdf)

成立条件与限制：

- `A,B` 必须条件独立且来自同一目标分布。共享确定性的 state 编码不破坏这个条件；故意强制互异或共享相关噪声，会使一致性项的期望不再是 `sum p_k²`。
- 不要先用有限样本频率 `p_hat` 再无修正地计算平方损失：频率估计的平方有额外方差项，会改变有限 `M` 的期望。上面的非对角配对形式避免了这一问题。
- 如果类别分布已显式可得，直接计算 Brier/CRPS 并反传通常更简洁，采样版需要证明它的计算或泛化收益。
- 样本化 reward 本身没有解决求梯度问题。若用 policy gradient，仍需要可计算的采样决策 log-probability，或另一个有效梯度估计器。只有完全黑盒随机输出而没有可训练概率，不足以直接应用 REINFORCE。
- 正确的二样本 score-function 梯度包含两条采样路径：`E[R_pair * (∇logπ(A|x)+∇logπ(B|x))]`；不能随意只更新其中一条。方差削减基线也不能依赖正在求 score-function 的那个随机动作。

因此，这是假说中最值得优先推导和验证的一条，但其价值应由直接 loss 的对照实验决定。

## 6. 其他可能机制，以及 RL 真正可能有用的地方

| 假说 | 技术内容 | 为什么可能用 RL | 能区分它的证据 |
|---|---|---|---|
| H1：直接报告分布的 proper reward | p 经过 Brier/log score 优化 | 可能只是训练系统以 reward 接口统一实现；数学上未必需要 policy gradient | 公开是否反传分布 logits、与直接 CE/Brier 的消融 |
| H2：多样本 proper/kernel reward | 样本与真值的一致性，减去样本间重复项 | 离散采样器参与训练；不枚举巨大输出空间 | reward 是否含 sample–sample 项，样本数与相关性的消融 |
| H4：多风险阈值的决策训练 | 在不同错误成本/拒答成本下作判断 | 非可微动作可使用 bandit/RL；覆盖完整阈值能约束概率 | 训练是否随机化成本、是否保持概率头与行动头区分 |
| H5：代码工作流的业务反馈 | 从代码组织的决策与后续成功、失败、返工学习 | 外部工作流的动作影响后续状态；可能需要探索及长期回报 | 反馈是否依赖动作、是否有外部轨迹、propensity 与 off-policy 修正；不据此假定模型内部有 CoT |

原 H3“离散隐变量/证据选择”保留为**通用 RL 研究旁支，不列作当前 JeV 主要假说**。如果它指模型内部采样一串规则、证据或思维步骤后再回答，就与创始人披露的定位不符，不应成为第一版学生的结构或数据需求。单个离散路由变量、随机噪声或普通隐状态并未因此被排除，但目前没有证据支持将其具体化为 JeV 的机制。H5 同样仅是外部系统未来可研究的分支，不是已知 JeV 训练来源。

H4 的校准联系也可以明确推导。给每个阈值 `t`，按 `a_t=1[p>=t]` 决策，损失定义为：

```text
C_t = (1-t)*Y*1[a_t=0] + t*(1-Y)*1[a_t=1]
2 * integral_0^1 C_t dt = (p-Y)²
```

覆盖完整风险阈值的决策损失可以恢复 Brier；只在一个阈值上训练“该不该行动”，通常不能唯一确定概率。这与行为校准/拒答研究相关，但仍不是 TypeSafe 的已知配方。[行为校准相关论文](https://arxiv.org/abs/2512.19920)

对于 H5，需要避免另一种夸大：**结果延迟到明天才到，不自动意味着必须 RL。** 如果只是 `(x,明日Y)`，等标签到达后做监督 log loss 完全可行。只有动作影响环境、反馈选择、观察机会或长期结果时，RL/上下文 bandit 的独特作用才出现。稀缺人工标签也不是使用 RL 的充分理由；RL 仍需要有意义的 verifier、奖励或可学习反馈。

最优收益策略也不保证校准。如果奖励额外偏爱高信心、自主执行或某个答案，properness 可能被破坏。工程上应考虑分别学习“事实概率”和“给定成本下的行动策略”，再由代码组合。

## 7. 相邻文献真正告诉了我们什么

| 一手文献 | 与本项目有关的发现 | 不能据此推出的结论 |
|---|---|---|
| RLCR：Beyond Binary Rewards | 对生成答案附加 Brier 信心奖励，可改善其研究设定中的校准 | JeV 使用 RLCR；或必须生成 CoT/信心字符串 |
| Rewarding Doubt | 以 RL 激励语言模型表达更可信的信心 | 其信心 token 是 JeV 的原生类别概率 |
| Uncalibrated Reasoning | 在随机二元结果任务里，GRPO 的组标准差归一化引入过度自信；与 PPO/RLOO、去归一化版本有对照 | 所有 GRPO 在所有任务中必然失效 |
| Outcome-based RL to Predict the Future | 研究延迟、噪声结果下的预测训练，并修改优势估计 | 只要是未来事件就不能用监督学习 |
| Verifiable Rewards for Calibrated Probabilistic Forecasting | 某 NFL 预测设定中，经验发生率目标及限制推理梯度的消融值得关注 | 单结果 Brier 在数学上不是 proper；该论文经验结论适用于全部任务 |

来源：[RLCR](https://arxiv.org/abs/2507.16806)、[Rewarding Doubt](https://arxiv.org/abs/2503.02623)、[Uncalibrated Reasoning](https://arxiv.org/abs/2508.11800)、[Outcome-based RL](https://arxiv.org/abs/2505.17989)、[Verifiable Rewards](https://arxiv.org/abs/2607.00164)。

特别要保留“目标正确”与“梯度估计正确”的区别。负 Brier 是 proper reward，也可能因为优势归一化、截断、采样相关、KL 正则或训练分布偏差而学歪。反过来，选了一个成熟 RL 优化器，也不能修复本来就只奖励 argmax 的错误目标。

## 8. 非自回归与并行：最小正确实现

必须分开四个轴：

1. **不同 state 的 batch 并行**：多个输入一起通过模型，决定硬件吞吐。
2. **同一 state 的多题/多候选并行**：所有评分都在这一轮张量计算中得到，不逐题调用聊天生成。
3. **同一 state 共享前缀计算**：避免对每个候选重复编码长 state，决定额外的算力节省。
4. **输出非自回归**：当前决策不依赖前一个生成出来的决策，不启动 token-by-token 的生成循环。

满足第 1、2、4 项，不自动满足第 3 项。Qwen 等因果注意力 backbone 可以一次 forward 读取多个独立输入的评分，从而满足输出非自回归；“使用 decoder backbone”本身并不意味着必须调用 `generate()`。

第一版因此采用无推理 token、无隐藏思维链的直接读出接口；System 2 的顺序步骤由代码显式更新 state 并再次调用。普通 hidden-state readout 仍然合法。将“单次 forward”设为我们可验证的实现要求，不将它误写成已知的 JeV 内部事实；迭代的非自回归采样器仍属未知，不因新披露而被数学上排除。

最小结构将一个输入批次展平：

```text
states[b]
  └─ questions[b,j]
       └─ candidate descriptions[b,j,k]
            → rows[r] = serialize(state_b, question_bj, candidate_bjk)

tokenizer(rows, padding=True)
  → 单次 model.forward(input_ids[R,L], attention_mask[R,L])
  → 在每行合法 readout 位置取隐状态
  → 共享 scalar scorer 得到 logits[R]
  → 按 (b,j) 回填 logits[B,Q,K]；无效槽位置 -inf
  → 每题的 K 轴 softmax
  → 并行计算 Boolean / Choice / Score / confidence
```

Boolean 可以统一成 no/yes 两个语义候选；Choice 是动态候选；Score 的序号只用于分组后的后处理与有序 loss。只要一批放得进内存，全部 state 的全部决策经过一次 backbone forward 同时返回。没有逐题 `generateText`，也不生成 JSON 数字作为模型预测。父任务里的可替换 teacher 脚本只是数据标注接口，不应直接成为学生推理结构。

若用 Qwen，右 padding 时不能盲取 `hidden[:, -1]`，应按实际有效长度 gather，或采用正确的左 padding/position ids。每行只读出一个 scalar logit；训练时去掉无用的全词表投影可进一步减少成本。批次过大时按 token 总数划定微批次，并准确报告实际 forward 次数，不以 HTTP 一次请求冒充一次模型计算。

后续要做到真实共享 state，使用 state-only 编码 + 并行题/候选 cross-attention，或可共享前缀的分支 attention：state 只看 state，每个分支只看 state 和自身。单纯把全部问题拼起来使用普通全注意力，会破坏问题独立性；即使直接挡住题间连边，state 回看问题也会形成跨层间接泄漏。

这些都是可实现的开源结构。它们满足什么并行性质可以实测；它们不是 TypeSafe 内部架构的证据。

## 9. 训练前的小实验：先验证目标，再讨论训练规模

### A. 纯数学检验，不训练任何模型

选已知发生率 `q∈{0.1,0.3,0.5,0.7,0.9}`，在 `(0,1)` 的网格上枚举预测 `p`。比较四条期望曲线：

- 单样本答对奖励：最大值在 0/1，q=0.5 时平坦。
- 直接负 Brier：最大值在 p=q。
- 对 A、B、Y 的所有有限取值精确求和的 `R_pair`：最大值也在 p=q，与 Brier 仅差比例/常数。
- 有限 M 的频率 `p_hat` 直接代入 Brier，与正确非对角配对估计比较，暴露有限采样偏差。

还要比较对 logit 的解析梯度与 score-function 梯度的完整枚举值；二者应一致。把 A、B 强制相关作为反例，可以直接看到前述证明何时失效。这里不用 LLM、API、GPU或自然语言样本，就能拒绝一批概念上不成立的“RLCD 复现”。

### B. 若之后决定训练，再用小型表格模型比较优化器

给每类状态设一个隐藏发生率，每条样本只揭示一次 Bernoulli 结果；使用固定训练标签和独立测试结果。比较：直接 CE、直接 Brier、仅正确性 REINFORCE、二样本 proper reward REINFORCE，以及“输出概率 token”的 RLOO/GRPO 对照。概率-token 策略与直接类别分布策略属于不同参数化，结果分表报告。

控制相同的结果标签数、初始化和计算预算，额外记录每个算法的采样数与梯度方差。测试同时测对真实 q 的误差、Brier、NLL、校准图、分辨率；不要只看 accuracy。若所有方法的 0.5 阈值准确率相近而概率误差差异很大，正是需要观察的现象。

### C. 架构检验独立于训练目标

对固定权重及相同输入，比较 `(B个state,Q题,K候选)` 单个 batch 前向与分开前向的数值一致性；记录 kernel/forward 次数、峰值内存和吞吐。增删、重排另一 state 或另一题不应改变本题结果。这样先证明“非自回归、批处理、题间独立”已经成立，再讨论共享 state 是否值得改结构。

这三层检验各自回答不同问题：A 验证奖励是否校准，B 验证优化器是否保留该目标，C 验证并行实现是否正确。它们不能互相替代。

## 10. 新披露之后的技术决策与数据纠错

**第一版学生只学决策映射。** 输入是调用时可见的 state、问题和动态候选；输出是完整候选分布及确定性类型后处理。跨步规划、工具调用与状态更新放在代码工作流。不要再为模仿 JeV 而加入 rationale 生成头、隐藏 CoT token、过程奖励模型或推理链数据集。teacher 可以使用自己的推理来做标注，但学生仅消费任务输入与最终标签/分布；这属于最终输出迁移，不能据此声称模仿了 teacher 的推理机制。

**训练目标与数据证据分开设计。** 一条样本至少保存输入快照、题型、候选语义、标签/分布、标签来源及其定义。数据需要明确区分以下三类：

| 目标含义 | 需要的数据 | 不能混淆为 |
|---|---|---|
| 可判定事实/规则 | 程序执行器真值、可审阅的人类标签 | teacher 自信程度 |
| 信息有限下的现实结果概率 | 决策当时的输入与后来结果；或已知生成机制的随机事件样本 | 因缺少证据就统一标 0.5 |
| 主观判断/歧义 | 明确标注规范，关键子集的独立多标注者意见 | 重复调用同一 teacher 得到的现实发生率 |

每个训练输入不必都有重复真实结果才能使用 proper loss；但若声称学到了歧义分布或校准，就必须有相应独立验证，不能只用 teacher 分布与自身拟合误差作证。教师多次采样估计的是该教师的输出分布；采样之间的相关性和系统偏差都不会被“次数足够多”自动消除。程序生成的确定性简单题适合初始化语义/类型能力，也不能单独证明不确定场景下的校准。

**把跨任务泛化放到数据组织里。** 覆盖问题改写、候选语义改写与换序、否定、证据缺失、证据冲突，以及只改变一个事实就改变答案的配对状态。改写保持同源分组；训练/验证/测试按原始文档、工作流与任务家族隔离。概率分布标签只在目标定义相同的改写之间传递；改变可见证据、候选集合或问题含义后，需要重新确定目标，不能机械复制旧分布。

**代码组合需要独立的工作流评测。** 为每一步保留调用前 state 快照与最终结果标签，避免把后续信息提前放进当前输入。工作流轨迹用于评测代码组合与选择效应，不要求学生学会生成这条轨迹。逐题边际校准不保证条件分支选中后仍校准，也不保证联合正确率；因此不能默认各题独立后直接相乘。要在真实分支策略下另外测最终成功率、选择后的错误率和错误成本。

最需要纠正的预算项是“为 latent reasoning 收集大量 CoT/过程奖励数据”：这不再属于 JeV 同类首版的必要投入。优先把数据预算用于任务覆盖、独立真值、歧义审阅和跨任务评测。上述取舍不决定 PPO/GRPO 等优化器；先完成分布目标、数据契约和直接 proper-loss 对照，再用受控实验判断 RL 的增益。

## 11. 哪些证据才足以改变我们的判断

最强证据是 TypeSafe 公开 reward/采样器/训练消融，或技术交流明确：是否显式计算完整 p、reward 是否含跨样本项、候选结果如何采样、真值和概率监督如何获得、是否有在线环境、与 CE/Brier 的公平对照。现在已经知道作者不允许 latent reasoning/CoT，因此不再把“内部思维链是什么”列作推进第一版的待答前提。

公开 API 行为只能提供较弱线索：分布的重复调用波动、批大小/题数/候选数的延迟曲线、结构变换的不变性，可能缩小推理实现的候选范围，但一般不能唯一识别训练目标。返回两位小数不证明“采了 100 次”；稳定输出不证明没有随机采样，可能有固定随机数、缓存、解析计算或较大样本量；吞吐高也不证明训练使用了 RL。

**当前建议的研究优先级：** 把“多样本 proper reward 与并行采样器的结合”列为值得验证的主假说，以直接 CE/Brier 的非自回归分布头为严格对照；先完成数学检验和批处理结构规格，不提前把任何一个优化器或结构命名为 TypeSafe RLCD 的复现。
