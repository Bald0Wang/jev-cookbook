# 项目演示指南

原任务是“1 人 1 天，DSH 决策插件开发，或者新增模式”。本项目按已经确认的“Jev 决策工具 + 可演示模式”交付。真实联调用于补齐可用性证据；大规模评测、对照实验和生产优化不属于本次必做范围。

## 可以怎样介绍这个项目

> 我做了一个 DSH × Jev 决策插件，提供通用判断和任务分流两个工具，并加了一个“Jev 决策协作”模式。主 Agent 可以调用 Jev 判断任务类型、目标是否需要澄清和复杂度，再根据结构化结果继续工作。项目包含能离线跑通的演示、异常处理、测试和可安装包。

## 五分钟演示顺序

1. 说明分工：DSH 负责 Agent 运行与工具编排，Jev 负责结构化判断，插件连接二者。
2. 展示 `npm run demo` 的三种分支，明确说这些是人工测试数据。
3. 展示 `examples/three-primitives.json`，解释同一 state 上的 Choice / Noul / Score。
4. 展示 DSH 合成配置中已加载的 `dsh-jev-decision`，以及“Jev 决策协作”模式。
5. 如果自己的 API 凭据已配置，按[最小验收指南](ACCEPTANCE.md)运行通用判断和分流检查，再展示一次 DSH 修改练习代码、通过测试的完整过程；否则说明当前演示覆盖安装与代码路径。

不要把 `mock_fixture` 描述为 Jev 的实测准确率。真实调用也不能凭一两个案例证明分类质量。课堂或项目演示时，可以仅展示离线工具调用，把使用付费账户的验证单列为扩展步骤。

## 验收清单

- 源码能安装依赖、编译并运行自动化测试。
- DSH 官方 CLI 能安装 `.tgz`，合成配置包含本插件。
- DSH 工具运行时能找到并执行 `jev_decide` 和 `jev_route_task`。
- 模拟模式不访问网络，输出显式标记来源。
- API 失败不生成有效路由建议，不进行自动重试。
- Jev 模式可以被发现并加载；卸载能清理自身注册。
- README 写明模型与 DSH 版本、安装步骤、密钥配置及当前验证范围。

## 可选后续扩展

若后续需要长期使用，再收集真实业务中的清晰任务、核心歧义任务和边界任务，由人标注期望分流，检查错误分支和不必要澄清，校准阈值。若升级 DSH，先重新核对插件服务和 preset 机制，不能只放宽版本号。
