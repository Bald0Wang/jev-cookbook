# 第五章 · 智能家居实验

> 对着 3D 房间说话，灯真的会灭——本章是第三章四个架构模式的**全家福实战**，也是全系列最好玩的一章。

## 01 官方 Demo 讲了什么

TypeSafe 官方的智能家居教学视频演示了三种模式：**单次调用多重评估**（"把咖啡烧上"一次调用里附带全部设备预判）、**复合拆分**（"关厨房灯然后锁书房门"复合概率 98%，转小模型拆分后并行评估）、**路由守卫**（"1989 世界大赛冠军"识别为信息请求转大模型）。本笔记本把视频里写死的演示数据全部换成真实调用——追踪面板里每个概率、每毫秒延迟都是 API 真实返回。

## 02 本章实验与实测数字

| 实验 | 场景 | 实测 |
|---|---|---|
| 投机提示单次调用 | "把咖啡烧上" | 一次调用捆绑 10 问，`appliance_action → turn_on`（置信 90.8%）采纳，灯/锁预判被代码端剪枝 |
| 复合拆分 + 并行 | "关厨房灯，然后锁书房门" | is_compound **97%** → 拆分 716ms → 并行两路 Jev，总耗时 1.4s |
| 串行工作流 | "先开客厅灯再关掉" | 两步作用于同一设备，依赖概率 **93%** → 串行栈执行，最终灯为关（顺序保持） |
| 状态查询 | "客厅灯开着吗" | 投机答案定位设备 + 本地 3D 状态直读，**零额外调用** |
| 传统 LLM 对照 | 同题双路 | Jev 141ms vs step-5-preview 16528ms——**慢 117× / 贵 135×**，且 LLM 输出存在格式与质量方差 |
| 语音输入 | 对着麦克风说话 | 阶跃星辰流式 ASR，16k 裸 PCM，首字 **0.52s**，中英文自动检测 |

最容易看混的一点：**串行 vs 并行由 Jev 判定**。每对子指令问一次 noul"A 必须先于 B 吗"，任一依赖 ≥60% 就走串行栈（拓扑序逐个派发，顺序决定最终状态）；全部低于阈值才并行。开灯再关灯判 93% 依赖——并行跑这两条，结果是不确定的。

## 03 3D 应用与配套

[`smart_home_demo/`](smart_home_demo/) 里是完整可运行的应用：`serve_smart_home.py`（静态页 + Jev/ASR/chat 代理，密钥只走环境变量）+ `smart_home_playground.html`（Three.js 3D 户型、点击设备交互、追踪面板、成本/token 实时统计）。笔记本内可以直接启动服务、复刻一次投机调用、并把应用 iframe 内嵌进来体验。

模型分工本身就是教学点：拆指令用 step-1o-turbo-vision（快），知识问答用 step-3.5-flash（准）——turbo 会把 1989 世界大赛答错成巨人队，**按需分配算力不只是省钱**。

## 04 核心价值

- **四个模式的现场版**：扇出、门控、路由、串并行编排，全在一间屋子里同时运转；
- **成本直觉**：页面右下角实时累计——单指令 Jev ¥0.0001~0.0007，传统 LLM 直答 ¥0.009~0.018；
- **可迁移的工程**：服务端代理解决 CORS 与密钥安全、AudioWorklet 采 16k PCM、SSE 透传流式识别——这套接线方式可以整体搬到你自己的项目里。
