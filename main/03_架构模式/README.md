# 第三章 · 架构模式

> 原语是词汇，模式是句法。本章把官方 Patterns 的四个架构模式合一册讲透——它们是所有 Jev 生产系统的通用骨架。

## 01 四个模式，一条主线

| 模式 | 一句话 | 没有它会怎样 |
|---|---|---|
| **推测性扇出** | 不确定用不用得上，先全问了 | 每类设备一次请求，往返次数爆炸 |
| **置信度门控** | 高置信自动执行，低置信转人工 | 错误决策直接进生产 |
| **复合评分** | 多个独立维度打分，代码加权 | 一个"综合分"无法归因，调优无从下手 |
| **意图路由** | 判断模型当守门员，决定走哪条路 | 所有流量都塞给昂贵的大模型 |

一条主线贯穿始终：**模型管语义判断，代码管规则与控制流**。这四个模式全部可以单独使用，也可以互相嵌套——第 5 章的智能家居是四者同时上岗的完整实例。

## 02 最好的理解方式：一个真实对照

智能家居 Demo（官方教学视频场景）把四个模式串成了一条链：

1. 用户说"把咖啡烧上"——Jev 一次调用捆绑**十个问题**：意图、是否复合、范围、房间、设备类别，外加灯/风扇/音响/家电/门锁五个动作预判。与指令无关的锁被问到 79% unlock / 21% lock 的模糊分布——**反正便宜，问都问了**，真用到门锁的指令来时不用再跑一趟（推测性扇出）；
2. 代码看到 category=appliance，采纳 appliance_action，其余四个预判静默剪枝（代码端组合）；
3. 用户说"关厨房灯然后锁书房门"——is_compound 以 98% 概率为真，转小模型拆成两条原子指令，并行再走一次 Jev（意图路由 + 复合处理）；
4. 用户问"1989 年世界大赛冠军"——意图判定为信息请求，全部智能家居预判作废，转大模型回答（门控）。

本章实验册把这条链逐模式拆开，每个模式配一个可独立运行的实验。

## 03 核心价值

- **架构词汇**：以后设计任何判断系统，脑子里有四张现成的图纸可套；
- **成本直觉**：投机式多问的成本账——Jev 按输入 token 计费（$0.042/M）、输出免费，多问五类设备的代价远低于多一次往返；
- **分工边界**：医疗类消息永远转人工这类**不可妥协规则，写进确定性代码，不写进提示词**。
