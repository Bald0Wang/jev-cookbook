# 第一章 · 认识 Jev

> **一句话**：Jev 不写文章，只做选择题。这一章用一次真实的 API 调用让你亲眼看到这句话是什么意思。

## 01 为什么要单独学"判断模型"

先看一个每天都在发生的场景：判断一条用户评论是不是垃圾广告。哪怕你在提示词里千叮咛万嘱咐「请只回答是或否」，底层逻辑依然是**写作文**——模型必须启动整套自回归网络，一个词一个词往外吐。有时候它乖乖输出「是」，有时候多吐一个标点、一个「好的，」前缀，你还得写正则去清洗。格式一旦失控，业务直接报错。

让擅长写长文的生成模型来做是非判断，不仅慢、计费贵，输出还随时可能失控。Jev 从根本上不做问答题，**只做选择题**：把待分析的文本作为 state，递给它几个固定选项，它像扫描一样直接给每个选项打出概率——单次前向、无循环、无采样、无文字拼接。

这就是"系统 1"的直觉判断。名字借自《思考，快与慢》：人的大脑里，快而省力的直觉判断和慢而费力的深度推理各司其职。以前所有判断都被塞给笨重的生成模型，Jev 把"点一下头、摇一下头就能搞定"的事接了回来。

## 02 本章实验与实测数据

| 实验 | 做什么 | 实测结果 |
|---|---|---|
| 实验 A：一次调用，三种原语 | 同一封 Stripe 投诉工单，同时问紧迫性（Noul）、诉求（Choice）、受挫度（Score） | 三份答案来自**同一次网络往返**，加问题几乎不加延迟 |
| 校准小实验 | 20 条人工数据感受"校准 ≠ 单次正确" | 预测 0.2 的组实际发生 10%——两组都"准"，组内单次仍会错 |
| 综合实验：赛事指挥台 | 三条夜跑现场消息，一次调用三问 + 代码阈值分流 | 脚踝扭伤 → 现场医疗（转人工），补水站缺杯 → 补给组，T恤咨询 → 自动 FAQ |

关键体验在"三份答案来自同一次往返"：System One 的每个问题对同一份 state **并行、隔离**地求值——这就是后面所有"投机式多问"技巧的物理基础。

## 03 核心价值

学完本章，你手里会有三样东西：

1. **一套提问纪律**：每个问题只问一件专家几秒内能下结论的事。复杂判断拆成原子问题，在代码里加权组合——优先级变了只改代码系数，不用碰提示词；
2. **一个路由守卫模型**：常识问题交给大模型，快而确定的判断交给 Jev——第 5 章的智能家居、第 9 章的 Agent gate 全是这个模式；
3. **对"校准"的正确预期**：给 0.8 概率的事件，一万次里约八千次发生。它不盲目自信，也不瞎谦虚——所以工程上用概率做群体决策，单点高风险交给阈值和人工。
