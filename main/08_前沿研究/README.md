# 第八章 · 前沿研究

> 教程教你"怎么用"，本章给你看研究者在问"**还能用来干什么、值不值**"。两个快照互为镜像：Jev-Mem 向外扩（判断模型管长程记忆），JevHarness 向内收（判断模型管确定性执行）。

## 01 Jev-Mem：给智能体装一套 System-One 记忆

上游 [libingzheren/Jev-Mem](https://github.com/libingzheren/Jev-Mem)（UT Dallas，[arXiv:2609.23986](https://arxiv.org/abs/2609.23986)，MIT）。核心问题：对话越滚越长，上下文要么塞爆（贵、慢），要么压缩（丢事实）。Jev-Mem 的答案是**写入/读取管线里全部用类型化决策**——该存什么（Score 留存分）、归哪类（Choice）、与新事实冲突吗（Noul），每个决策点都是第一章的三原语。

两册笔记本的实测结论（2026-09-25，真 Jev + DeepSeek + Qwen3-Embedding）：

- **四臂对照**（16 轮中文对话）：Jev-Mem **0.80** vs 朴素 RAG 0.64——增益集中在时间与多跳题，决策面与 embedding 质量正交；全上下文天花板 0.96；
- **长程缩放**（48→384 轮）：全上下文每题 token 线性涨到 **81 倍**，Jev-Mem 恒定 **~120 tok**；
- **真 LoCoMo**（419 轮样本）：全上下文 0.60 vs Jev-Mem **0.98**——长对话里"记忆"不是优化项，是正确性前提。

**核心价值**：记忆系统不必用大模型写摘要——用判断模型做存取决策，token 恒定、事实可溯。这是"原子判断 + 代码组合"在记忆架构上的完整落地。

## 02 JevHarness：开发策略与执行策略分离

上游 [TianyuCodings/JevHarness](https://github.com/TianyuCodings/JevHarness)（NanoJev 作者的新项目），社区贡献的分析文档。核心主张：开发阶段用强编码 LLM 写出决策 Harness；在线阶段执行显式的流程、特征与结构化判断，不让强模型参与每一步。若 Harness 用 Jev 节点，在线仍调 Jev——它降低的是逐步调用强 LLM 的需求，而非移除推理服务。

**核心价值**：第 7 章四个游戏环境的"确定性引擎 + 类型化判断"就是最小形态的 Harness；这份评估文档回答了把它工程化时的边界问题（什么该留在线上、什么该离线写死）。
