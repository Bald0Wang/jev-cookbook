# Werewolf · Jev 狼人杀实验报告

## 1. 这是什么

1 名真人 + 5 个 Jev 玩家的完整一局狼人杀：固定种子、服务端规则引擎、夜间技能（狼人刀/预言家查验/女巫药）与白天投票全部由 Jev 的 Choice/Noul/Score 决定，发言由模板生成（无 DeepSeek key 时显式标注 template_fallback）。

## 2. 实验意义

狼人杀是**信息不对称下的多轮对抗**：每个 Jev 玩家只拿自己的私有信息，判断却要公开接受检验（投谁、信谁、刀谁）。它检验的是判断模型在对抗博弈里的两个能力：基于不一致性改判（投票与发言矛盾要被抓出来），以及身份隔离下不"开天眼"。

## 3. 要回答的问题

1. 5 个 Jev 能否独立完成夜间技能与白天投票（而不是复制粘贴同一个答案）？
2. 发言（模板）与投票（Jev）分离的架构下，决策质量如何？
3. 真人能不能从 Jev 的公开判断里读出有用的博弈信息？

## 4. 实验怎么做的

`node server.mjs`（端口 4175，seed 20260921），浏览器开新局，真人（村民）发言"先听大家的分析"，随后连续推进：白天发言 → 投票 → 夜晚 → 天亮，直到终局。全程截图存 `figures/`。

## 5. Jev 每一步怎么工作

- **夜间**：狼人刀人、预言家查验、女巫用药——各自用 Choice 在候选目标里选，规则引擎校验合法性；
- **白天投票**：每个 Jev 对每个存活玩家做判断（Choice，候选"放逐谁"），返回置信度；
- **白天发言**：无 DeepSeek key 时用模板（accuse_player / question_claim / share_result），显式标 `template_fallback`——**发言是话术，判断是 Jev**，两层分离。

## 6. 实验结果与说明

完整一局、**狼人胜利**：

- 第 1 天：5 个 Jev 发言各不相同（ accuse / question / share_result / support），置信度 43–48%（低信息轮次的诚实表现）；真人被 3 票放逐，身份公开为村民——**误杀**：自称预言家的 Jev-3 说真人是好人也没拦住；
- 夜晚：Jev-3（自称预言家）被刀——狼人的刀验证了它此前的威胁性；
- 第 2 天：Jev-1 投票判断转而怀疑 Jev-2，理由是「它的投票和之前的发言不一致」（vote_inconsistency）——**跨轮一致性检查真的在起作用**；
- 投票判断分布：Jev-5→目标置信 93%、Jev-4→81%、Jev-1→75%——置信度分层清晰，不是均匀乱投。

## 7. 成本与耗时

一局约 2 分钟、20+ 次 Jev 决策（夜间技能 + 两轮投票），单局成本约 $0.001 量级。无 DeepSeek key 时发言零成本（模板）。

## 8. 结论与后续

**判断与话术分离**的架构在对抗博弈中成立：Jev 的投票/技能决策有真实博弈行为（跨轮一致性检查、置信度分层），发言模板只负责表达。后续：配 DeepSeek key 观察自然语言发言对投票的影响；提高狼人 AI 的协同（夜间 Jev 之间目前不共享判断）。
