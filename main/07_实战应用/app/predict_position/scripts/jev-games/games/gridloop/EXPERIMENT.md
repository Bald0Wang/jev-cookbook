# Gridloop · Jev 贪吃蛇实验报告

## 1. 这是什么

一个可以直接打开的贪吃蛇游戏：点击「Jev 自动驾驶」，服务端把当前棋盘、蛇身、食物、合法方向打包成 state，用 TypeSafe 的 Choice（选下一步方向）+ Noul（判断当前是否陷阱局）让 Jev 自己开车，浏览器实时显示它的决策理由。

## 2. 实验意义

贪吃蛇是"局部判断 vs 全局规划"的最小实验场：模型只看当前局面（蛇身、食物、recentHeads），不知道未来——它能不能**只靠一次 Choice 就活下来并吃到食物**？这直接检验第一章的核心主张：结构化判断足以支撑闭环控制。

## 3. 要回答的问题

1. **决策质量**：Jev 每步在合法方向上的概率分布是否合理（朝食物、避开身体）？
2. **存活能力**：纯靠 Jev 逐帧决策，蛇能活多久、吃多少？
3. **延迟**：每步决策的往返耗时能否跟上游戏节奏？

## 4. 实验怎么做的

`node server.mjs`（读项目目录 `.env` 的 `TYPESAFE_API_KEY`，浏览器不接触 key）。两阶段验证：

- **API 直连**：向 `/api/move` 发一个固定局面（蛇 3 节、食物 (12,5)）连测 3 次；
- **自动驾驶长跑**：浏览器点击「开始游戏」+「Jev 自动驾驶」，连续运行约 40 秒观察轨迹，截图存 `figures/`。

## 5. Jev 每一步怎么工作

一次请求两个问题：`move`（Choice，criteria 按合法方向动态生成——plannedDirection 的描述是"最安全的已知路线"，其余是"除非明显撞墙/成环"）；`trap`（Noul，判断当前是否处于危险/循环局面，服务端检测到 loop 时会在指令里附加破环提示）。

## 6. 实验结果与说明

- **API 直连**（同一局面 3 次）：choice 分别为 right/right/down（置信 0.68/0.68/0.68），trap noul 0.19——朝食物方向、非陷阱，一致且合理；
- **自动驾驶长跑**：分数 004 → **030**，蛇长 5 → **33 节**，全程零死亡（`figures/autodrive-length07.png`、`figures/autodrive-longrun-score30.png`）；
- **决策理由可读**：面板实时显示「Jev 选择向下，继续接近信号点」「Jev 判断当前有风险，采用安全路线向上」——概率权衡直接翻译成人话。

## 7. 成本与耗时

3 次直连延迟 0.847 / 0.522 / 0.289 s（首次含连接建立）。按输入约 400 token/次计，单步成本约 $0.000017（输入 $0.042/M、输出免费）；40 秒长跑约 20 步，总成本不足 $0.0004。

## 8. 结论与后续

Jev 逐帧 Choice 驾驶贪吃蛇**完全可行**：长跑 33 节零死亡证明局部判断足以支撑闭环。后续可对比：换 Laya 本地模型（32.8ms 延迟更适合高频帧）、把 trap 判断升级成"回头路检测"的 Score。
