# 智能家居 3D 演练场实验报告

## 1. 这是什么

官方 Smart Home Demo 的完整可运行复刻：Three.js 3D 户型 + 语音/文字指令 + 真实 Jev 投机管线。追踪面板里每个概率、每毫秒都是真实 API 返回（原参考版是写死的演示数据，本项目全部换真）。

## 2. 实验意义

把第 3 章四个架构模式放进**一个同时运转的系统**：投机扇出（一次调用十问）、门控（信息请求转 LLM）、路由（复合拆分）、串并行编排（noul 判依赖），并且全程可视化——概率、延迟、成本在追踪面板实时呈现。

## 3. 要回答的问题

1. 一次调用捆绑十个问题，Jev 的分布质量够不够支撑"代码端剪枝"？
2. 复合指令的拆分-并行链路与串行栈判定的实测延迟？
3. 与传统 LLM 直答（step-5-preview）同题对比，差距量化是多少？

## 4. 实验怎么做的

`serve_smart_home.py`（静态页 + Jev/ASR/chat 代理，key 走环境变量），浏览器实测全部预设指令场景 + 语音输入（阶跃 ASR，16k 裸 PCM），截图存于本仓库历史与 [jev-playground](https://github.com/Bald0Wang/jev-playground) 报告。

## 5. Jev 每一步怎么工作

一次 `/v1/systemone` 捆绑：intent（Choice）+ is_compound（Noul）+ scope/room/category（Choice）+ 五类设备动作预判（Choice×5）。代码端按 intent 路由：命令 → 剪枝取相关类；复合 → LLM 拆分 → noul 判"A 必须先于 B 吗"（≥60% 串行栈）；信息请求 → 转 step-3.5-flash；状态查询 → 本地直读零调用。

## 6. 实验结果与说明

| 场景 | 实测 |
|---|---|
| "把咖啡烧上" | appliance turn_on 置信 90.5%，全链路 ~170–250ms |
| "关厨房灯然后锁书房门" | 复合 97% → 拆分 716ms → 并行两路，总 1.4s |
| "先开客厅灯再关掉" | 依赖 93% → 串行栈，最终灯为关（顺序保持） |
| "客厅灯开着吗" | 本地直读，零额外调用 |
| 同题 LLM 对照 | Jev 141ms vs step-5-preview 16528ms（慢 117× / 贵 135×），派发结果一致 |
| 语音 | 首字 0.52s，中英自动检测 |

## 7. 成本与耗时

单指令 Jev 约 ¥0.0001–0.0007（输入 $0.042/M、输出免费）；LLM 直答 ¥0.009–0.018。页面页脚实时累计会话成本。

## 8. 结论与后续

投机提示 + 代码端剪枝在真实 API 上成立，且**判定质量足够**（无关预判给出的是"保持现状"高置信而非噪声）。后续：WebSocket 双向流式语音（零延迟上屏）；JevBench 中文扩展。
