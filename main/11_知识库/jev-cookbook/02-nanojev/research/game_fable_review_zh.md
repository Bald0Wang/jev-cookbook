## Fable 的结论与必须纠正的地方

Fable 赞成先网格、默认均匀最优动作目标、程序真值主监督、继续旧 Instruct 学生与同原始 Instruct 重新训练两臂对照，以及记录真实动作轨迹。它提出先约 400 states/1800 questions 排查生成器，再扩到 6000–12000 题。该数量是工程起点，不是证明模型能力所需的数据定理。

以下回答不能原样执行，本文已独立纠正：

| Fable 原建议 | 复核后的决定 |
|---|---|
| 回放原 144 states；旧同族 test 下降超过 2 点就停训/调回放 | **只回放原 64 个 train states**；旧 dev 可用于预先定义的回归选择，旧 calibration/test/OOD 不能进入训练。依据旧 test 调整模型也会把它变成开发集，不能再当未见测试 |
| 相对八方向用 Score | 方位不是线性有序等级，应使用 Choice；Score 只用于显式有序的距离或风险区间 |
| $25 不支持大规模 Jev 标注 | 这是无成本依据的判断。此前 144 个状态标注实际 $0.003219762，40 次高 K probe 实际 $0.004269636；单次输入长度不同，按真实 token/请求构成估算，不能由预算数字直接下结论 |
| 2000 次 rollout 与 DP 差大于 .02 就一定有 bug | 随机抽样本来可能超过该差值。使用二项置信区间、跨状态多重比较与 DP/转移实现单元检查；先区分统计偏差和确定性错误 |
| 每步加载 checkpoint | 服务启动加载一次并保持模型驻留；**每步做实际前向**。把磁盘加载算进每步不代表实际服务设计 |
| 网格 horizon = 2×oracle 最短路+2；第二次访问相同状态即失败 | 统一按尺寸设置固定上限，例如 `4×边长²`。在线控制不读取 oracle 路长；确定性贪心可记录重复位置，随机滑移中重访不能自动判错 |
| 井字棋 heldout 完全无法说明泛化；旋转版和新地图差 10 点就证明泄漏 | 未见对称等价类仍可测有限状态域内泛化，只不能外推到通用规划。两类成绩差是诊断信号，**泄漏须由分组/哈希证据证实** |
| 非自回归读出是不用 PPO 的理由之一 | PPO 完全可以优化离散动作策略；当前不优先用它，是因为已有低成本精确教学目标，需先确认任务覆盖与闭环错误，不是接口不支持 RL |

这些纠正是本代理的复核，没有额外付费请求让 Fable 背书。不会把其回答中的所有句子都当作采纳决定。

## 第一阶段：最小网格环境

先用 4×4、5×5 的自写地图训练，保留同尺寸新地图及 6×6 尺寸外推两种测试。墙、可进入的危险格、起点和两个具名目标均来自生成器。状态用紧凑 JSON 或等价文字表达，提供坐标系说明；question 决定本局去哪个目标，以及是否把危险格视为禁区。中英文及同义改写继承同一地图分组。

第一版先固定基础“到指定目标”规则；绕开危险格作为明确的第二个机制，不在结果出来后才选择好看的玩法。包含必须先远离目标才能绕障、不同最优首步并列、不可达等情形，避免模型只学朝目标的曼哈顿方向移动。

| 原语 | 首版问题 | 精确标签 |
|---|---|---|
| Choice | 下一步执行哪个动作才能按规则到达目标？ | 到达目标或不可达时 STOP；否则在所有最短路径首步中均匀分配质量 |
| Boolean | 指定动作会不会进入危险格？指定目标是否可达？ | 一步转移规则 / 离线可达性判断；问题中明确动作，不依赖 Choice 的输出 |
| Score | 剩余最短路处于哪一档？ | 例如 0、1–2、3–5、6 及以上；不可达另用 Boolean 或在该题条件中排除，避免暗造有序含义 |

每步候选由合法移动与 STOP 组成；移动合法性只看越界/碰墙和明示的环境规则，不能靠全局可达性筛选。**STOP 在所有状态都可选**，否则“只在无路时出现 STOP”本身就泄漏答案。完全孤立时只有 STOP，可以单列为环境边界样例；它不计入需要模型理解的成功证据。

网格最优动作目标为：

```text
A*(s) = 所有合法且使最短距离减少 1 的动作
q(a|s) = 1 / |A*(s)|，a 属于 A*(s)；其余为 0
到达目标或无路：q(STOP|s) = 1
```

这是我们选择的**专家动作策略**。如果有两条等长路径，均匀分布只是教学约定；学生偏好其中一条仍可能同样会玩。因此同时报告最优动作集合命中率、路径代价与专家分布对齐，不能只用精确分布相似度判定游戏智能。动作 softmax、熵和集中度不能显示成“本局获胜概率”。

运行环固定：启动时加载学生一次 → 环境序列化当前 state → 构造题目与合法候选 → 一次实际模型前向 → Choice argmax → 执行动作 → 记录和渲染。不得用 BFS fallback、更正学生动作或静默缩短轨迹。BFS 只能作为**明确选中的 oracle 基线模式**，展示时不能混进学生成绩。

每局固定上限按尺寸设置；超时、过早 STOP、非法输出、循环分开记录。成功局报告步数减最短路长度；失败局另报，不能用仅成功局的低 regret 隐藏大量失败。不可达地图报告正确 STOP 率，与可达地图到达率分开统计，防止全选 STOP 获得表面高分。

## 查询分布与训练安排

Fable 的 1800 题建议适合先验证 schema、分组和监督，但不够支撑广泛能力声称。工程上先跑这个量级的完整流程，随后再扩到约 8000 题；不要因为 API 便宜就跳过生成机制审计。

一个可调整的 2000 states/8000 questions 扩展配置如下，所有数字都是工程默认，不是隐藏验收配额：

| 查询族 | states | 每 state 题数 | 必须变化的机制 |
|---|---:|---:|---|
| 业务政策 | 300 | 4 | 同一事实换政策导致答案变化、否定及缺信息 |
| 证据关系 | 300 | 4 | 支持/矛盾/未说明，主语交换、否定范围 |
| 工具前置条件 | 300 | 4 | 可执行/缺参数/权限/状态冲突，多项条件组合 |
| 动态候选 | 250 | 4 | K、标签重命名、难负例、集合变化后重算目标 |
| 解析事件概率 | 250 | 4 | 抽样机制、观测条件变化、Boolean 概率及明确结果分布 |
| 网格局面 | 600 | 4 | 地图/目标/障碍机制与非最优轨迹中的恢复状态 |

训练先按生成机制、原始状态、完整轨迹和地图对称轨道划组，再划 train/dev/calibration/test。改写、中文/英文、旋转、目标交换及同一局后续状态不能随意跨分区。未见机制与未见实例分别报告。游戏训练不只取专家轨迹，还从训练地图采样偏离最短路径的可达局面，并离线重新求专家标签，缓解单步错误累积。

程序可验证的样本以程序 gold 为主监督；Jev 在预先固定的分层子集上另存分布，用于研究教师贡献与协议差异。若要比较 Jev 输出分布监督，应保留独立同数据分支，不能把错误 teacher 与 gold 混成同一个真值。保留舍入原始向量及覆盖审计，非单位和明确使用 proxy 或单列的 interval 实验。

最小训练比较为：旧冻结学生；从旧学生继续训练；从原始 Instruct checkpoint 加同结构新头训练。后两者用相同新增数据、旧 **train** 回放、样本曝光预算与单 seed。继续训练臂已有历史成本，不能称两者总训练经历完全相同；报告累计与新增成本。

建议 backbone LR `1e-5`、head LR `1e-4`、dropout 0、按题平均损失、有效 batch 48 题，以 token/path 预算决定 microbatch。500 步作为初始上限，而不是对 1800 题无条件重复十几遍；第一轮可限制约 3 次训练集曝光并在新 dev + 旧 dev 上检查。已有头无需再强制从头 warmup；新随机头先做短 head warmup。所有更改只用开发集决定，最终测试不能用于反复调参。

先把单步监督和真实闭环跑通。若新状态分布上的恢复样本已补齐，闭环仍显著差，再比较环境回报优化；PPO 或其他 RL 只是独立游戏训练分支，不能命名为已复现的 RLCD，也不能用高回报代替概率校准。

## 第二阶段：真实概率与井字棋

首版网格先保持确定性。若要在 UI 上显示“未来成功概率”，必须另定义转移机制、剩余 horizon 与执行策略。例如固定滑移概率与固定专家策略，用有限时域 DP 计算：

```text
V_0(s) = 1[s 已到目标]
V_h(s) = Σ_a π(a|s) Σ_s' P(s'|s,a) V_(h-1)(s')
```

目标为吸收态；终止失败为 0。标签记录环境版本、策略版本、horizon。若 π 是学生策略，checkpoint 变化后通常必须重算；若 π 是固定专家，该标签描述专家的未来，不能显示成当前学生成功率。独立 seeded rollout 用置信区间检查 DP 与采样实现，再对模型预测报告 NLL/Brier/可靠性，而不是拿动作熵做替代。

井字棋随后接同一 Choice API：枚举可达非终局，minimax 离线给所有等价最优动作；对 D4 对称规范化后的棋局分组。学生与随机、固定弱对手、minimax 对手分别真实对局。可以报告未见等价类上的有限状态泛化，不能声称通用规划。学生运行时不调用搜索；胜负只来自整局结果，候选概率仍是动作策略。

## 验收与可推翻测试

先固定完整评测种子与分层，不挑成功片段替代均值。random、BFS/minimax oracle、旧冻结学生、扩展学生在同一批环境运行。展示可以播放已录轨迹，但必须标“回放”；在线模式接受新 seed/地图并实际调用已加载模型。

每步日志至少含 checkpoint 标识、state 哈希、题目/候选、原生概率、选中动作、环境下一状态、模型与端到端延迟；按局保存成功/失败原因。报告 batch 吞吐与单局逐步延迟的不同测量，GPU 计时需同步，不能把多环境批次吞吐称为单游戏反应速度。

建议先把同尺寸新地图 85% 到达率、循环率低于 5% 作为展示工程目标，把 6×6 的 65% 作为探索目标，**均不是模型能力保证**。低于目标时发布失败结果，先查生成器、表示和错误恢复，不删难图。真实继续条件是相对旧学生/random 的稳定提升、未牺牲预先规定的旧 dev 回归指标，并有足够局数体现误差范围。

能推翻“模型已经学会任务”的检查：

1. 必须先远离目标才能绕障的地图单列；若只会朝目标走，容易地图成功不能抵消该失败。
2. 坐标原点平移、同一地图的语义保持变换、候选重排与中英改写分别测试，区分表述敏感与环境难度。
3. 按最短路径长度、障碍拓扑、可达性和规则族分桶；同时记录强制偏离一步后的恢复率。
4. 检查 D4 规范化和轨迹源组是否跨 split；性能差异本身不是泄漏证明，分组证据才是。
5. 打乱目标或 question 的负对照必须改变预测；若不变，模型可能忽略指令。

一天内可信的是：生成器可复核、实际 checkpoint 控制闭环、明确的有限留出结果，以及失败可重放。一天内不能凭一个网格或井字棋演示证明通用 Jev 能力、普遍校准、Doom 水平或专有 RLCD 已还原。
