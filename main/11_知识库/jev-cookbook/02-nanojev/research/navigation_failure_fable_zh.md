# 导航失败：Fable 短审查与 V3 可执行决定

2026-09-17。这是对已经观察到的 V2 失败的后续分析。V2 的失败结果保留；下述 V3 属于下一轮设计，不是已经获得改善的实验结果。当前执行协议和已运行配方仍以主任务产物为准。

**先做同一 0.6B 的状态表示与起点覆盖实验，同时固定比较 greedy、学生原分布采样和 uniform random。** 不能只把循环归咎于坐标文字，也不能先换大模型后宣称已经找到原因。禁止在线 BFS 动作 fallback。

## 真实观察与解释边界

当前学生训练约 600 steps，400 个 4×4 训练地图每图只取一个起点；候选为方向词，状态为文字/ASCII 地图。结构仍是可训练 Qwen3-0.6B 与动态候选读出、集合交互头，非自回归预测。

主任务给出的此时快照：Jev 离线网格最优动作标签约 97.5%，学生离线单步约 75%。但实际导航中，teacher 学生在新 4×4 地图仅 2/20 到达，6×6 仅 1/20；gold 学生分别 5/20、3/20；uniform random 在相同初局和 `2×size²` horizon 下为 90%/65%。学生出现大量循环。成绩来自实际对局；20 局不足以给总体成功率一个很窄的置信结论。

最强证据是**单步评价没有预测闭环可用性**。随机游走在足够长的有限网格中可以偶然走到目标，确定性贪心却可能反复访问同一状态；这支持检查执行策略和状态分布，而不单独证明随机策略更懂规划。把单步正确率简单乘成 `0.75^H` 只能作独立错误假设下的直觉说明，不能当作这些相关轨迹的真实成功率公式。

需要从日志验证：重复状态是否反复选择同一动作；错误是否集中在特定方向/边界；必须先远离目标的地图是否特别差；训练地图上未见起点与真正新地图是否差距明显。BF16 混批可有数值差异，若以完全相同状态诊断确定性循环，应抽查固定批次/FP32 下的行动一致性，避免把数值扰动误认成策略理解。

## Fable 的意见和独立纠正

Fable 认为起点覆盖不足、偏离训练状态及确定性循环的组合最值得先检验，未排除容量限制；赞成先做 V3 表示×覆盖消融，再做结构化诊断基线，最后才扩更大 LLM。它也支持 controller 单列、旧 test 只做诊断，以及不急着加入 PPO。

以下不能原样执行：

1. **不能用减少地图数量来配平覆盖。** 补问建议 `1 start×400 maps` 对 `8 starts×50 maps`，同时改变了地图多样性，无法识别起点覆盖贡献。应保持同一组 400 地图，单起点臂重复曝光，多起点臂扩大位置覆盖；相同更新/样本曝光，另外报告 token 数和 GPU 时间。
2. **训练地图仍差不等于数据无关。** 首条答复把训练集全起点失败用作排除数据主因，因果判断过强。标签问题、目标歧义、优化和表示问题都可能导致训练失败。补问已明确撤回这种单独归因。
3. **图基线不要输入 BFS 答案特征。** 补问提及“BFS 特征上的小模型”；若特征是到目标的距离或最优首步，就已经把规划交给求解器。可学习图基线只能使用坐标、局部邻接、墙/可行走、目标标记等原始信息；完整 BFS 另列 oracle。
4. **greedy 胜过 uniform 不是所有概率策略用途的必要条件。** Fable 的短答使用了该强门槛。应同时预注册三种执行策略：如果学生采样比 uniform 更有效，这是分布的可用证据；它不能抹掉 greedy 的失败，也不能变成模型已经学会稳定最短路的证明。
5. **性能相同不能单独排除 grounding。** 把方向替换成 A/B/C/D 后成绩相同，只说明这次干预未改善；双方都不会任务、存在不同补偿路径或统计功效不足时，也会相同。方向混淆同样不能直接定位为 set head 问题。

## V3 最小实验

先固定新的 train/dev/test 地图池及 D4 分组，所有起点、语言改写、坐标变换继承整图分区。已经反复查看的 V2 test 保留为历史诊断，不用它选温度、训练步数或表示后再称为未见测试。

| 臂 | 表示 | 起点覆盖 | 其余条件 |
|---|---|---|---|
| A | 原 ASCII / 方向词 | 每图 1 个 | 同一地图集合、同模型初始化、同程序 gold |
| B | 明确坐标与候选目的地 | 每图 1 个 | 同 A |
| C | 原表示 | 每图至多 8 个不同起点 | 同 A |
| D | 明确坐标与候选目的地 | 每图至多 8 个不同起点 | 同 A |

不足 8 个可用非终局起点时记录实际覆盖，不造重复点冒充新起点。单起点臂重复训练样本来匹配曝光量；多起点臂在同图上覆盖新位置。新增坐标文字会改变有效 token 长度，不能同时声称“完全相同样本曝光”和“完全相同有效 token 数”而不说明补偿方法。主比较固定题目/更新曝光，报告实测 token 与时间；若结论主要来自更多算力，再补同 token 预算的敏感性检查。

表述明确零起始 `(row,col)`，北为 `row-1`，并把每候选的一步结果写出来，例如 `向北，从 (2,1) 到 (1,1)`。这些由当前状态和环境转移直接计算，**不含 oracle 信息**。不得添加最短距离、最佳方向、该动作是否最优、从新位置到目标是否可达等需要求解的问题答案。

第一轮保留现有 backbone 和读出，不为这个干预重写 shared-prefix、set head 或 attention kernel。先判断表示与训练覆盖是否改善新地图闭环，再做架构比较，避免同时改变多个因素后无法归因。

## 同时固定三种执行策略

所有模型在同一组新地图、固定 `2×size²` horizon 上比较：

- **Greedy：** 原始概率 argmax，保留当前失败基线。
- **Student sample：** 直接从学生概率采样，固定 `T=1`、预先指定每局随机种子，不在旧 test 调温度或 epsilon。
- **Uniform random：** 从同一个合法动作菜单均匀采样，使用独立、预先固定的随机数流。

随机策略应跑预先指定的多种种子并按地图聚类评估；不要把同一地图的多个随机重复当成独立地图。visit penalty 若加入则另列第四个 controller 实验；不静默替换前三者，不用在线 BFS 修正动作。

报告到达率、失败计满 horizon 的平均步数、成功局单列的路径效率、唯一访问状态数、重访率和周期循环，以及 `Σ_{a∈A*(s)} p(a|s)` 的最优动作概率质量。后者由离线 oracle 评分，不在执行前告知学生。只看 argmax 最优率不能描述整个分布；只看采样成功也不能证明模型掌握最短路径。

随机采样改变访问状态分布，因此不能以“controller 后访问状态上的最优率变化”直接推断权重变好了。需要在同一固定状态集上比较分布质量，并在各自轨迹上另报闭环表现。

## 失败后的明确顺序

如果 D 在新 dev 上仍未改善，先检查标签、状态序列化、方向混淆、损失/梯度和训练地图未见起点上的拟合。不要仅凭一个百分比认定模型太小。随后加一个**不含 oracle 特征**的简单图编码/GNN 诊断基线，输入原始局部图结构，并把 BFS 作为独立正确性上界。

图基线若明显更好，支持“该任务需要更合适的空间表征/归纳偏置”，不证明通用 LLM 无法学习；图基线也失败，则继续检查实现、标签和训练，而不是直接宣布任务定义错误。更大同家族 LLM 是后续容量对照，用同数据与读出比较，报告实际计算成本，不与图改造同时上线。

首个继续条件是预先选定的新 dev 上出现可重复的闭环提升、循环减少、概率质量改善，并保留非游戏任务回归。Fable 提出的 40%/60% 阈值是临时工程建议，不是统计定理或本项目已预注册门槛；不把它们追认为用户要求。若没有明确提升，保留失败报告，停止扩标签规模，先解决哪类表征与状态覆盖能让模型学会这个有限任务。
