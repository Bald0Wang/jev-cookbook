# 工作流数据、概率指标与游戏回放独立审查

日期：2026-09-17。审查对象为 `build_workflow_decisions.py`、`evaluate_pipeline_decisions.py`、`evaluate_game_policy.py`，并只读核对推理器、训练数据解析器、已生成数据和随机/oracle 回放。此次未调用教师 API，未运行 GPU，未修改既有工作流输入、训练器或网页。

**结论：没有发现把 oracle 动作冒充学生动作的执行分支，也没有发现工作流数据中的跨 split 语义组重复。已补强评估输入校验和回放审计；同时确认井字棋 OOD 的完整轨迹经常进入训练棋盘组，不能把它称为全程未见状态评测。**

## 工作流数据与标签

对已冻结的 1,008 个工作流状态重新构造了独立语义组：智能家居按房间、设备、授权和人数；目录检索去掉 SKU 后按颜色、尺寸、状态、加急标记；随机抽球按颜色与约分后的计数比例。重新得到 1,008 个唯一组，与声明的源组隔离一致。全部 `gold_probs` 的候选映射、取值范围和归一化均通过检查。

家居命令和时间不改变当前声明的标签规则，按更粗的相关配置分组是合理的。目录源组原字符串含 SKU，但本版其他配置本身全部唯一；剥离 SKU 后仍无重复，并非靠唯一编号掩盖同一配置。随机抽球将等比例计数合并到同组，避免把同一条件分布换个总球数放入其他 split。

随机抽球明确没有实际抽样观察：`gold={}`、`gold_label_kind='unobserved'`，使用解析条件分布作为目标，没有伪造一个硬结果。其 OOD 主要是中文标题/记录表述，英文值和题目仍大量保留；manifest 已说明这是语言表述变化，不是未见任务族。

## 概率评估中已修复的缺口

`evaluate_pipeline_decisions.py` 保留原有数学指标，并补上以下约束：

- 拒绝重复预测行、同一 state 跨 split、重复候选 ID、错误长度、NaN/越界/非归一化学生概率；若同时保存 logits，验证 softmax 与概率一致。
- Gold 分布必须声明支持的目标类型；`deterministic_truth` 必须 one-hot。当策略/解析分布缺失时，拒绝把代表性 `gold_index` 偷换为确定性真值。
- 原先文档称无效教师只在教师指标中排除，但直接传入非归一化 `teacher_probs` 会使整个评估报错。现在显式隔离无效教师目标并统计原因，同时保留独立 gold 指标；不重新归一化损坏的教师分布。
- CE/KL 原本已有 `1e-12` 的对数下限，现在明确披露，并报告落到该下限及零预测概率上的目标质量。真实无限损失不能被悄悄展示为普通有限 KL。数值误差产生的极小负 KL 截为 0。

公式本身核查正确：总变差为 `0.5*sum(abs(q-p))`；期望多类 Brier 为 `sum(p²)-2 dot(q,p)+1`。对于程序给定的条件分布，后者是已知 q 下的期望评分；对于均匀最优动作目标，它只是指定参考策略下的损失，不是现实事件校准。解析 ECE 衡量预测首选事件的置信度与该事件条件概率之间的分箱差异，没有将其伪装成已经观察到真实抽样结果的经验 ECE。

现有分组指标同时提供 family/type 与总体问题均值。总体 gold 指标混合了确定性真值、解析分布和策略目标，只适合看明确的数学损失汇总；解释能力或校准时应使用相应分组。此次没有拟合温度，也没有用 test/ood 选择 checkpoint。

## 学生动作的真实性与回放修正

学生分支构造的公开请求严格只有 `id/state/questions`。虽然渲染器也能计算 oracle 元数据，这些字段未进入模型请求。动作直接取自 `DecisionPredictor.predict` 返回结果，然后交给 `step`；求解器用于标注动作质量和控制固定 minimax 对手，不为学生选择失败后的替代动作。推理器从本地 checkpoint 加载参数，返回其实际 logits softmax，没有 teacher/gold 输入，也没有文本生成循环。

现在进一步要求：返回的 state ID 与请求一一对应，动作分布覆盖且仅覆盖全部合法候选，数值有限归一化，实际执行的学生动作必须是该返回分布的 argmax，且执行记录至少有一次本地非生成式前向。任何不一致都会报错，不会回退到 oracle。

仅一个合法动作时，学生/随机/oracle 的受控方直接走该动作，计入 `forced_decisions`，不调用模型。井字棋对手始终采用同一确定性 minimax 规则；其仅有一步的情况现在另计 `opponent_forced_decisions`，轨迹中也标记 forced，避免与模型选择混在一起。

井字棋原指标“保住初始 minimax 价值”在初始价值为 -1 时自动满足。现增加按初始 -1/0/+1 分层的结果、初始非败局面的保值率，以及初始价值减实际结果的平均差，原指标保留供向后比较。

## 固定 cohort 与真实轨迹重叠

选择规则保持为：每个冻结的 test/ood split，按文件顺序取前 20 个可达网格起点和前 20 个井字棋起点，总计 80 局；选择发生在推理之前，不按模型表现挑选。新增记录完整初始 episode ID 和初始状态列表的 SHA-256。所有井字棋策略使用相同的完美对手规则，网格步数上限固定为 `2*size²`。

已重跑无模型的随机和 oracle 基准，并将它们与原结果逐条比较：**初始 episode ID、所有轨迹动作、全部旧核心指标完全一致**。变化仅为新增的审计字段和细分统计。

| 基准与分组 | 初始状态进入训练组 | 轨迹曾进入训练组的局数 | 重叠的受控方非强制决策状态数 |
|---|---:|---:|---:|
| 随机，井字棋 test | 0/20 | 7/20 | 1 |
| 随机，井字棋 ood | 0/20 | 19/20 | 15 |
| oracle，井字棋 test | 0/20 | 6/20 | 3 |
| oracle，井字棋 ood | 0/20 | 20/20 | 26 |
| 随机/oracle，网格 test/ood 各组 | 0/20 | 0/20 | 0 |

这不是初始状态分区失败：早盘井字棋继续走下去会自然进入中后盘。当前起点隔离仍成立，但 TTT OOD 只能称为早盘起点与较大动作集合的泛化测试。JSON 现在分别记录全部 pre-action 状态、受控方非强制决策状态、实际学生模型决策状态的训练组重叠；后续学生结果应按自身真实轨迹统计。

固定随机种子下，原随机网格成功率为 test 90%、ood 65%，oracle 两者 100%；随机平均路径效率分别约 0.367 和 0.274，oracle 为 1。网格小、允许步数较多，随机也可能最终撞到目标，不能只展示成功率而隐藏路径效率。TTT oracle 仍可能输掉初始必败局，这正是必须按初始 minimax 价值解释结果的原因。

## 标注日志快照

只读审查时，游戏日志累计有 3 次 `TEACHER_REQUEST_FAILED`，均明确记录 `unknown_cost=true`；当时保存了 1,158 个不同状态，没有重复保存 ID。第一次失败的网格状态后来已有成功标签，另两条 TTT 状态在该快照时尚无标签。标注进程可能随后继续推进，因此这不是最终完成率报告。

现有失败行只有通用错误码，无法区分服务端状态、响应解析或持久化失败，也不足以推断状态内容触发了错误。应依据后续明确错误信息处理；本次审查没有自行重试 API，未把失败请求费用计为零。

## 验证范围

用可手算的二项分布检查解析 Brier/ECE，用多最优目标检查集合命中，用错误教师向量检查局部隔离，验证重复/非有限/伪硬目标/logits 不一致均被拒绝。240 道已有真实模型预测通过新版评估的兼容性回归。

回放控制流另用明确标为测试用的假引擎检查公共请求字段、调用计数和非 argmax 动作拒绝；该测试没有保存任何学生基准结果。随机/oracle 基准来自真实环境推进。新增学生训练臂的实际 GPU 回放仍由主流程执行，此审查没有把代码检查或测试假引擎当成学生模型成绩。
