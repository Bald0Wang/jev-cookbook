# 当 AI 需要做决定：Jev Cookbook 开源教程

**从第一个类型化判断，到游戏、智能家居、Agent 和长期记忆，亲手搭起一条可观察的 AI 决策链。**

## 开源初心

当 AI 从聊天窗口走进真实应用，它面对的任务也变了。一个 Agent 要决定下一步调用哪个工具；扫雷程序要在未知格子中选择落点；智能家居系统要判断一句话指令对应哪台设备、哪种动作。这些时刻，系统需要的往往不是一段流畅的回答，而是一个**能被程序理解、检查和执行的判断**。

怎样描述当前状态？候选动作应该怎样设计？模型给出的概率能否直接当作“做对的把握”？如果判断错了，谁来阻止危险动作？这些问题散落在模型、应用和工程实践之间，也正是我们发起 **Jev Cookbook** 的原因：把抽象的“让 AI 做决定”，拆成可以学习、运行和复盘的具体实验。

在这里，模型负责理解状态并回答类型化问题；规则、权限、执行和反馈仍由程序管理。一轮判断可以写成：

```text
观察状态 → 提出有限候选的问题 → 获得选项与概率 → 程序检查并执行 → 观察新状态
```

生成式大模型依然适合写作、解释和开放式规划。Jev Cookbook 关注的是另一类高频环节：**当问题可以明确表达为一次选择或打分时，如何让判断进入可靠的应用闭环。**

## 项目简介

Jev Cookbook 是一套由 Datawhale 社区开源的 Jev 决策模型中文教程。全书 11 章，从 State、Choice 等基础概念出发，逐步走向 Cookbook 配方、模型评测、游戏与应用、Agent 集成、前沿研究和本地模型实践。每一章都尽量回答同一个问题：**这个实验在验证什么，观察到了什么，又不能由此推出什么？**

在这个项目中，你将获得：

- 🔍 **一套判断问题的表达方法：**把业务状态、候选答案、概率输出和程序策略分清楚。
- 🧭 **循序渐进的学习路线：**从三个问题原语，到完整的状态—判断—动作—反馈链。
- 🛠️ **可动手的案例：**在 RAG、工具选择、智能家居等任务中，找到模型判断适合进入系统的位置。
- 🎮 **看得见的项目演示：**通过扫雷、贪吃蛇等游戏和网页应用，观察每一步动作怎样产生、执行与反馈。
- 📊 **读懂结果的评测方法：**同时看正确率、概率校准、延迟、成本和失败案例，而不是只看一张排行榜。
- 🧠 **通向前沿的实践入口：**用 Jev-Mem 理解长期记忆的写入与检索，并进一步接触 Agent 集成和 Laya 本地模型路线。

开源地址：[datawhalechina/jev-cookbook](https://github.com/datawhalechina/jev-cookbook)。[十一章总目录](../../../README.md)可以作为你的学习导航。

## 项目受众

如果你会读基础 Python，知道如何调用一次模型 API，就可以从第一章开始。你可以是正在做 Agent 或 RAG 的开发者，想研究模型评测的同学，也可以只是好奇：“除了生成一段话，模型还能怎样参与应用决策？”

前几章不要求你有模型训练经验。遇到概率、校准、风险控制等概念时，教程会把它们放回具体问题和实验中解释；走到本地模型章节，再逐步接触数据、训练与部署。

## 学习指南

11 章内容可以按五个阶段阅读。每一阶段都为下一阶段准备一个新的问题，而不只是增加一组 API 用法。

**第一部分：先学会提出判断题（第 1～3 章）。** 从 Jev 是什么开始，认识 State 与 Noul、Choice、Score 三种问题原语；再看模型输出的概率如何进入程序控制流。读完这一部分，你应该能说清楚：模型究竟判断了什么，代码又负责什么。

**第二部分：让判断进入实际任务（第 4～5 章）。** 第四章用 18 个 Cookbook Notebook 展开 RAG、风险控制和结构化处理等配方；第五章把判断接入智能家居，让一句自然语言指令经过意图识别、动作派发和设备状态更新。这里开始，你会看到一个模型调用如何变成完整的应用流程。

**第三部分：用实验和项目检验它（第 6～7 章）。** 第六章学习比较模型：除了答对多少，还要看概率是否可信、响应是否够快、代价是否合适。第七章则把这些问题放进 12 个游戏与应用项目：模型选动作，环境检查并反馈，下一轮判断再从新状态出发。

**第四部分：走向研究与 Agent 系统（第 8～9 章）。** 从 Jev-Mem 等研究案例理解决策模型如何参与记忆、检索和证据判断，再把类型化判断接入 Agent 的工具路由与安全门。你会发现，模型给出一个高分选项，只是系统做出动作的开始。

**第五部分：理解模型与证据从哪里来（第 10～11 章）。** 沿着 Laya 的数据构建、训练、校准和评测路线，认识本地决策模型怎样形成；最后回到知识库，学习核对资料来源、实验版本和结论范围。这样，当你展示自己的效果图时，也能讲清楚它所依据的实验。

你可以按顺序学习；如果想先获得直观印象，不妨先看下面三个演示，再带着问题回到对应章节。

## 实战项目效果演示

### 智能家居：一句话怎样变成设备动作？

在智能家居实验中，你可以从 3D 房间看到设备状态，再顺着执行追踪查看指令怎样被理解、选择分支并派发动作。它把“判断”从一个抽象的模型输出，变成页面上能追踪的状态变化。

![智能家居演练场：3D 房间、决策追踪与设备状态](media/chapter-05-smart-home.png)

**图 1｜智能家居演练场。** 图中展示的是本地模拟引擎的交互流程，便于观察系统组成；它不代表在线 API 的性能测量。

### 第七章：在游戏里看清一次决策

第七章收录了 12 个项目，涵盖贪吃蛇、扫雷、狼人杀、迷宫、Browser Use、Mario 和智能家居等不同场景。游戏尤其适合入门：状态会变，候选动作有限，动作是否有效又能由环境立即裁定。

![Jev Games 统一入口：贪吃蛇、扫雷和对照实验](media/chapter-07-jev-games-overview.png)

**图 2｜Jev Games 统一入口。** 从一个界面进入不同游戏与对照实验，先看整体，再追踪单次判断。

![扫雷项目：棋盘状态与 Jev 动作记录](media/chapter-07-minesweeper.png)

**图 3｜扫雷决策界面。** 棋盘提供数字约束，模型在候选格子间做判断；动作记录让你看到它选了哪里，游戏规则则负责裁定这一步的结果。成功揭开一格，不等于模型已经掌握所有局面；下一步仍要根据新棋盘重新判断。

如果你正在开发 Agent，可以把棋盘换成网页，把“揭开格子”换成“点击按钮”：状态、候选动作、程序检查和环境反馈，仍然是同一条链。[第七章项目总览](../../../07_实战应用/README.md)列出了全部案例与入口。

### 第八章：长期记忆不只是保存聊天记录

对话变长后，一个新的难题出现了：哪些信息值得记住？提问时又该取出哪一部分？Jev-Mem 把判断放进记忆写入、关系组织和检索路由，让生成模型在证据足够时再组织答案。

![Jev-Mem 写入、记忆与检索架构图](media/chapter-08-jev-mem-architecture.png)

**图 4｜Jev-Mem 的写入、记忆与检索。** 这张架构图帮助你定位每次判断发生在何处，以及它怎样影响最终回答。图片来自 [Jev-Mem 上游项目](https://github.com/libingzheren/Jev-Mem)。

教程还保存了实验数据，方便你从“架构看起来合理”走到“结果究竟怎样”。在 48～384 轮的合成对话实验中，每个规模有 10 道题。全上下文方案的每题输入从约 1,144 增至 9,778 tokens；Jev-Mem 约为 120 tokens。到 384 轮时，两者本轮评审分分别为 0.88 和 0.90。输入减少了，但 Jev-Mem 的单题查询更慢，建立记忆也有一次性成本。

![Jev-Mem 长程缩放实验：答案质量、每题输入 token 与查询延迟](media/chapter-08-jev-mem-scaling.png)

**图 5｜长对话变长时，质量、输入量和查询延迟如何变化。** 这是一轮本地实验，每个规模只有 10 道题；图表用于理解趋势和代价，不能当作多次重复后的稳定结论。

另一个 LoCoMo 样本包含 419 轮对话和 10 道题。本轮 Jev-Mem 与全上下文的评审分是 **0.98 对 0.60**，每题输入约 **784 对 19,775 tokens**；但查询延迟是 **3.83 秒对 0.60 秒**，Jev-Mem 建立记忆还需要约 **494 秒**。

![LoCoMo 样本 0：Jev-Mem 与全上下文的答案质量、输入成本和查询延迟](media/chapter-08-locomo-sample-0.png)

**图 6｜同一小样本上的质量与代价对照。** 它显示了这组题目中筛选证据的潜力，也提醒我们把查询延迟和建图成本一起算进去。10 道题不足以代表完整 LoCoMo 结果，分数也受本轮 LLM 评审影响。[第八章 README](../../../08_前沿研究/README.md)提供了实验过程、Notebook 和更多图表。
