# 第九章 · Agent 集成示范

> 前面各章都是"我们写个 demo 用 Jev"，本章反过来：**在别人的 Agent 框架里，让 Jev 在动手之前先做一次判断**。两册示范，一个共同主题。

## 01 Pi + Jev：工具执行前的 gate

Pi 是可扩展的 Agent 运行时。本册给 Pi 写一个 TypeScript 扩展（配套 [`pi_jev_demo/`](pi_jev_demo/)），在**每次工具调用之前**插一道 Jev 判断：该不该执行（Noul）、参数有没有危险（Noul/Choice）、要不要换条路（Choice）。

为什么这道 gate 值钱：Agent 的越权与事故都发生在"执行"之后——把一次 0.65s、结构化、可审计的判断插在执行之前，成本几乎为零，事故面大幅收窄。扩展代码与笔记本分离，判断逻辑可独立审计。

## 02 DSH × Jev：真实会话的决策复盘

DSH 是带决策栈的 Agent 工程（配套 [`apps/dsh-jev-decision/`](../../apps/dsh-jev-decision/)）。本册三步走：把 DSH 每个决策点改写成 Jev 类型化问题 → 用同一插件的真实会话跑通验证（2026-09-24 归档，非人工 mock）→ **失败复盘**：哪些决策 Jev 接得住，哪些必须留在代码里。

运行模式刻意保守：`DSH_JEV_RUN_MODE=live` 至多 4 次真实请求、无 key 即停不回退；阅读模式重放归档响应不发新请求。

## 03 共同的教训

两册 converge 在同一句话上：**Jev 负责"动手前的快判断"，控制流与不可妥协的规则永远留在代码里。** 想从工程方法层面深挖，看第八章 jev_harness 的"开发/执行分离"论述。
