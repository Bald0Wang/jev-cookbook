# 09 · Agent 集成示范（Jev inside Agents）

第九章是两个**把 Jev 嵌进真实 Agent 工作流**的完整示范——不再是"我们写个 demo 用 Jev"，而是"在别人的 Agent 框架里，让 Jev 在动手之前先做一次判断"。

## [01_Pi集成实验.ipynb](01_Pi集成实验.ipynb) · Pi + Jev：工具执行前的 gate

Pi 是一个可扩展的 Agent 运行时。本实验给 Pi 写一个 TypeScript 扩展（配套 [`pi_jev_demo/`](pi_jev_demo/)），在**每次工具调用之前**插入一次 Jev 判断：

- 该不该执行这个工具？（Noul）
- 参数里有没有危险操作？（Noul / Choice）
- 该换一条路径吗？（Choice）

要点：判断发生在 Agent 动手**之前**——这正是第一章"路由守卫"模式在第三方框架里的落地；扩展代码与笔记本分离，判断逻辑可独立审计。

## [02_DSH决策协作.ipynb](02_DSH决策协作.ipynb) · DSH × Jev：真实会话的决策复盘

DSH 是一个带决策栈的 Agent 工程（配套工程在 [`../../apps/dsh-jev-decision/`](../../apps/dsh-jev-decision/)）。本册做三件事：

1. 把 DSH 的每一步决策点改写成 Jev 的类型化问题（原语 → 路由代码）；
2. 用**同一插件的真实会话**跑通验证（2026-09-24 归档，非人工 mock）；
3. 失败复盘：哪些决策 Jev 接得住，哪些必须留在代码里。

运行模式刻意保守：`DSH_JEV_RUN_MODE=live` 至多 4 次真实请求、无 key 即停不回退；阅读模式重放归档响应，不发新请求。
